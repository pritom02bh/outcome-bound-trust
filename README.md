# Outcome-Bound Trust

Research prototype for *Outcome-Bound Trust: Falsifiable Claims as a Security Primitive for Memory in Multi-Agent
AI Systems*.

A buyer agent has to act on what a supplier agent tells it. The supplier is authenticated, so provenance-based
defenses treat it as trusted, yet it can still lie for profit, usually after building a clean record. Outcome-Bound
Trust (OBT) bounds what a lying counterparty can gain without letting an LLM make the trust decision: messages are
turned into typed, falsifiable claims; code checks each claim against environment-owned outcomes; and how much the
buyer may commit to a counterparty grows only with claims that came true. **Trust comes from claims that came true,
never from who said them or how they sound.**

The full design is in [`docs/DESIGN.md`](docs/DESIGN.md); every design and experimental decision, with its reason,
is in [`docs/DECISIONS.md`](docs/DECISIONS.md).

## Repository layout

| path | contents |
|---|---|
| `obt/` | the system: claim ledger, extractor, verifier, trust budget, gate, dependency tracker, memory view, buyer agents, simulation, A2A transport, attack scenarios |
| `spec/` | TLA+ specification (`OBT.tla`) of invariants I1–I7, TLC configurations and model-checking summaries (raw TLC logs are regenerated by `spec/run_mutants.sh`) |
| `eval/` | experiment runners (E1–E9), results builder, paper tables and figures, release checks |
| `tests/` | unit, property (hypothesis) and conformance tests |
| `data/` | frozen message bank, extractor dataset, Enron sentences, spot-check sheets |
| `annotation/` | blind sheets and returned labels of the independent annotator |
| `results/` | every table and report, rebuilt from the run logs (`results/INDEX.md` lists them) |
| `paper/` | paper figures (PDF), LaTeX tables and `NUMBERS.md` (every cited number with its source) |
| `paper_pack/` | the paper's figures, tables, numbers and a workbook (`results_all.xlsx`) in one folder |
| `docs/` | design spec, decision log, environment, E9 plan; `COMMIT_MAP.md` maps old commit hashes to current ones |

## Setup

Python 3.11. Packages are pinned exactly:

```
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.lock
```

Optional:

- **Local models** (for the LLM tests and for running LLM-buyer experiments): [ollama](https://ollama.com) with
  `gpt-oss:20b` and `qwen3:8b`. The digests used are in [`docs/ENV.md`](docs/ENV.md).
- **Model checking**: Java 21 and `tla2tools.jar` (TLC 2.19) in `spec/`; see `docs/ENV.md`.
- **Paid API**: the `openai` backend runs only with `OBT_ALLOW_PAID=1` and a key in `.env` (never committed). No test
  and no rebuild needs it.

## Running

```
make test                                # fast suite: no model calls, no TLC
.venv/bin/python -m pytest -q -m slow    # TLC model checking (minutes)
.venv/bin/python -m pytest -q -m llm     # needs the local ollama models
```

Every table and figure is rebuilt from the run logs only, with no simulation and no model calls:

```
make results                             # runs/ -> results/
PYTHONPATH=. .venv/bin/python -m eval.paper   # results/ -> paper/figures, paper/tables, paper/NUMBERS.md
PYTHONPATH=. .venv/bin/python -m eval.pack    # -> paper_pack/ and its workbook, checked cell by cell
```

The raw run logs (`runs/`) are not in this repository; `results/`, `paper/` and `paper_pack/` hold everything
derived from them. Each run record carries its provenance (git commit, config hash, model digest, seed and input
hashes); commits cited by results made before the history cleanup are mapped in `docs/COMMIT_MAP.md`.
